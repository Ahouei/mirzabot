03 Residuals the response under-states

Act on these — they finish the CRITICAL block properly

  1. C4 is not race-safe. The provision-before-charge bug is genuinely fixed, but "atomic conditional decrement" is inaccurate — WalletService.change reads then writes in Python with no row lock. Two concurrent wallet buys can still double-spend on PostgreSQL. Fix: a single atomic UPDATE "user" SET balance = balance - :amt WHERE id=:id AND balance >= :amt (act on rowcount), or SELECT … FOR UPDATE before the check.
  2. cubepay settlement is still silent. settle_tuple (cubepay only) passes bot=None and skips _report. Fix: thread the bot into settle_tuple like settle does, and call _report there.

Test-suite check. The response reports "45 passed." I did not execute the suite (still a static pass) but read tests/test_money_path.py in full: the gateway-provision and top-up tests are genuine — they drive the real settle() and assert the criteria that matter (invoice activated, order paid, wallet untouched / credited once), and would fail on the pass-1 code. The third test only unit-checks the charge refusal — it does not exercise the full flow or the concurrency case. Net: honest tests, not gamed; the one missing dimension is exactly the C4 residual above.
