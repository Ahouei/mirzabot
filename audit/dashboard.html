How completion is calculated. Each of 96 parity features is scored by fidelity to baseline — Done/Improved = 1.0, Risky = 0.7, Partial = 0.5, Buggy = 0.2, Missing = 0.0 — and averaged. Additions in the rewrite (ledger, idempotency, webhook-secret, encryption, plugin registry) are excluded from the denominator. The score measures how much surface area is present, not operational readiness of the revenue path.
Critical caveat: three independent defects each break online payments — an undefined settle_wallet_topup, gateway purchases that never set invoice_id (so they mis-route to the broken top-up path), and settlement that never notifies the buyer. The test suite is green because it never exercises that branch.  ·  Scope: static pass only — no code executed, no DB or panels contacted. Panel-adapter correctness and end-to-end payment flows are deferred to a dynamic pass.
